1. 利用コンテキスト分析

ゲームの世界観とHUDの関係

ちいかわ風の丸っこいキャラクターが下克上するというゆるさ×ガチのギャップがこのゲームの核心。 HUDもこの世界観に合わせ、「和紙に墨で書いたような」ゆるかわテイストで統一する必要がある。 Apex Legendsの機能設計（アビリティCD表示の仕組み）は参考にするが、見た目は「ちいかわの世界に存在しそうな掲示板」のイメージ。

プレイヤーの視線パターン

90秒の制限時間アクションで、視線は画面中央のキャラクターとその周辺に80%以上集中する。 HUD確認は瞬間的（0.2-0.5秒）で行われる。「読む」ではなく「見る」レベルで認識可能にする。

情報の優先度

優先度情報参照タイミング必要な認知速度
S残り時間常時（5秒ごと）0.1秒で認識
Sアビリティ状態使用判断時（3-5秒ごと）0.2秒で認識

2. 現在のHUD問題分析

問題1: 視認性の欠如

main.js:838-839 — ctx.fillStyle = "#1a1a1a" で直接Canvas描画。 背景色 #d8c5b4 とのコントラスト不足。バックパネルなし。

問題2: ミニマップとスコアの衝突

constants.js:12-13 — ミニマップ X=662。 main.js:850 — スコア右端 X=652。10pxしか離れておらず、4行のステータス（Y=30-92）がミニマップ（高さ96px）と重複。

問題3: アビリティが全部テキスト

main.js:858-903 — 「突撃 [右クリック] 準備完了」をテキスト表示。 辻斬り返し（SPACE）はHUD表示すらなし。漢字一文字のアイコン化で0.1秒認識を実現する。

問題4: 残り時間が左上の端

main.js:839 — 左上 (20, 35)。最重要情報が視線中心から最遠。上部中央へ移動。

3. デザイン方針: ゆるかわ和風HUD

世界観との整合

  • 和紙パネル: rgba(245, 238, 225, 0.82) の白〜クリーム半透明。黒半透明は使わない
  • 墨文字: #3a2a1a（焦げ茶）をメインカラーに。黒より柔らかい
  • 角丸きつめ: border-radius: 12-14px。キャラの丸っこさに合わせる
  • 手書き風フォント: ゲームで使用中の chika-Regular.ttf を前提
  • アイコンは漢字一文字: 「突」「揆/十/討」（キャラ別Q）。リアルなアイコン素材は使わない
  • キーバインド内蔵: Apex方式でスロット上部にキー表示（「右」「Q」）。アビリティバー自体が操作ガイドを兼ねる
  • 淡い色使い: 枠線は rgba(160, 130, 90, 0.45)。ゴールドではなく「枯れた金」

レイアウト配置（前回と同じ情報設計）

位置要素理由
上部中央残り時間最重要情報。視線移動最小
左上石高 + 身分スコア系を集約。ミニマップと衝突回避
右上ミニマップ位置維持（学習コスト回避）
下部中央アビリティバー 2スロット（突撃 + Q固有能力）漢字アイコン + キーバインド内蔵 + CD表示。操作ガイドを兼ねる

4. Canvas実装指針

  • 和紙パネル: ctx.fillStyle = "rgba(245, 238, 225, 0.82)"; ctx.roundRect(x, y, w, h, 12); ctx.fill();
  • 枠線: ctx.strokeStyle = "rgba(160, 130, 90, 0.45)"; ctx.lineWidth = 1.5;
  • 墨文字: ctx.fillStyle = "#3a2a1a"; フォントは既存の FONT_FAMILY = "'Chika', ..." を使用
  • テキスト視認性: 白ストローク（ctx.strokeStyle="#f5eee1"; ctx.lineWidth=3; ctx.strokeText(); ctx.fillText();）で背景に溶けない
  • CDオーバーレイ: "rgba(200, 190, 170, 0.7)" で和紙の重ね塗り風に。黒暗転ではない
  • Ready発光: ctx.shadowColor = "rgba(200, 160, 60, 0.25)"; ctx.shadowBlur = 10; 控えめに
