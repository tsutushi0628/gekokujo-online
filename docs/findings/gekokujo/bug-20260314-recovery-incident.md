## 根本原因分析

### 直接原因

`git checkout -- public/concept-final.html` の実行により、未コミットの全変更が不可逆的に消失した。

### 間接原因

1. **原則1違反**: ユーザー確認を取らずにキャラサイズ修正を勝手に実行した
2. **破壊的操作の安易な使用**: `git checkout --` は未コミット変更を不可逆に消す破壊的コマンドであるにもかかわらず、影響範囲を確認せずに実行した
3. **コミット遅延**: 23操作もの変更を一度もコミットせずに作業を続けていた

---

## 再発防止策

### 必須対応

1. **原則1の厳守**: いかなる変更も、ユーザーの y/n 確認前に実行しない
2. **破壊的gitコマンドの事前確認義務化**: `git checkout --`, `git restore`, `git reset --hard` 等の未コミット変更を消すコマンドは、必ずユーザー確認を取る。特に `git checkout -- <file>` は該当ファイルの未コミット変更の有無を事前に `git diff --stat` で確認する
3. **頻繁なコミット**: 大きな変更は5操作ごとにWIPコミットする
4. **サイズ変更のリバートは個別Edit**: ファイル全体を checkout で戻すのではなく、変更した箇所のみ Edit ツールで個別に戻す

---

## 教訓

- `git checkout -- <file>` は「そのファイルの未コミット変更を**全部**消す」コマンド。部分的な取り消しには使えない
- 未コミット変更の一部だけ戻したい場合は、`git stash` や Edit ツールで対象箇所だけ修正する
- コンテキスト圧縮後は特に慎重に行動する。前の文脈が失われているため、安易な操作は禁物
- セッションログ（.jsonl）は最後の砦。ここに `old_string` / `new_string` が残っていたおかげで復旧が可能だった
